# Расчёты населения Древней Руси по археологии

Заявочная система по варианту «История и Культура, 2». Пользователь набирает конфигурацию из
удельных княжеств Древней Руси с археологически измеренной площадью укреплений, а система
оценивает численность населения по методике исторической демографии.

Курс «Разработка Интернет Приложений», МГТУ им. Н. Э. Баумана, ИУ5-52, осень 2026.

## Предметная область

| Сущность | Что это | Таблица |
|---|---|---|
| Княжество | удельное княжество с площадью укреплённой части стольного града | `principality` |
| Оценка населения | расчёт численности по выбранным княжествам | `population_estimate` |
| Включение в оценку | связь «оценка ↔ княжество» с числом учитываемых поселений | `principality_inclusion` |
| Археолог | пользователь системы, он же модератор при `is_moderator` | `archaeologist` |

Два поля по предметной области у княжества: `settlement_area_hectares` — площадь укреплённой
части стольного града в гектарах, `settlement_type` — тип поселения (`capital`,
`fortified_town`, `hillfort`), который задаёт долю жилой застройки в расчёте.

## Формула

Численность населения считается по площади застройки, а не умножением на «плотность»:

```
дворов    = площадь_га × 10 000 × доля_застройки(тип_поселения) / площадь_двора
население = дворов × 4,4 × число_поселений
```

Константы взяты из методики В. А. Кучкина: средняя площадь двора — 400 м², средний размер
семьи — 4,4 человека. Площадь двора остаётся параметром ввода: меняя его, пользователь видит,
насколько оценка чувствительна к допущению — именно из-за этого параметра оценки численности
Киева у разных исследователей расходятся в разы.

## Данные

Десять княжеств с площадями укреплённой части из свода А. В. Кузы «Древнерусские городища
X–XIII вв.» (ИА РАН) и работы М. Н. Тихомирова «Древнерусские города». Восемь опубликованных,
один черновик, одно удалённое. Доли жилой застройки по типам поселений — оценочные величины.

Изображения княжеств — Wikimedia Commons, лицензии и авторы перечислены в
`media/principalities/CREDITS.csv` родительского каталога. Вертикальные ролики для ленты
собраны из этих же изображений.

## Запуск

```bash
docker compose up -d
docker exec -it minio_storage mc alias set myminio http://localhost:9000 root rootpassword
docker exec -it minio_storage mc mb myminio/principality-media
docker exec -it minio_storage mc anonymous set public myminio/principality-media

go build ./... && go vet ./...
go run ./cmd/principality-web
```

Приложение — `http://localhost:8080`, консоль Minio — `http://localhost:9001`,
Adminer — `http://localhost:8081`.

## Страницы

| URL | Что показывает | Шаблон |
|---|---|---|
| `GET /principalities/feed/{principalityId}` | лента: вертикальное видео княжества на весь экран | `principality_feed.html` |
| `GET /principalities/draft` | черновик княжества с разделёнными полями | `principality_draft.html` |
| `GET /principalities?minArea=` | плитка в два столбца с фильтрацией по площади | `principality_catalog.html` |

Параметр `?next=true` у ленты открывает следующее княжество после указанного.
Фильтр `minArea` работает на сервере и возвращает введённое значение обратно в поле.

## Дизайн

Стилистика повторяет **Arzamas** (`arzamas.academy`) — просветительский проект по истории
и культуре. Три цвета с точными кодами:

| Роль | Код | Откуда снят у донора |
|---|---|---|
| тёмный фон | `#000000` | фон главной страницы донора — у нас лента и панель вкладок |
| primary | `#FECF00` | кнопка «Скачать приложение» в шапке — у нас все кнопки и активная вкладка |
| фон страниц | `#E8E8E1` | подложка карточки `.journal-item` в секции журнала |

Форма карточек — скругление 10 px, доминирующее у донора. При наведении обложка приглушается,
а название подчёркивается — так же, как в правилах `.item:hover` донора. Полный перечень
скопированного — в шапке `static/css/principalities.css`.

## Структура

```
cmd/principality-web/main.go        точка входа
internal/app/api/server.go          три роута и запуск gin
internal/app/config/config.go       адрес сервера и базовый URL Minio
internal/app/handler/handler.go     три обработчика, фильтрация и подсчёт лайков
internal/app/repository/repository.go  модель княжества и коллекция в памяти
templates/                          три страницы и общая панель вкладок
static/css/principalities.css       вся стилистика отдельным файлом
```

Данные лабораторной 1 живут в памяти, без базы. Комментариев в коде нет намеренно —
он должен читаться сам.
